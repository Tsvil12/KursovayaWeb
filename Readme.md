## 1. Тема

Разработка веб-сервиса для ресторана "Паб Русский" с разделением прав для клиентов и администратора.

---

## 2. Стек технологий

| Компонент | Технологии |
|-----------|------------|
| Backend | Kotlin + Spring Boot 3.2, PostgreSQL, JWT, Spring Security |
| Frontend | Vue 3 + TypeScript, Vue Router, Vite |
| Инфраструктура | Docker, Docker Compose |

---

## 3. Соответствие требованиям

| Требование | Реализация |
|------------|------------|
| **Роли (минимум 2)** | Администратор (управление меню) и Клиент (оформление заказов, просмотр меню) |
| **Сущности (минимум 5)** | User, Category, Dish, Order, OrderItem |
| **Связь между сущностями** | Одна категория -> много блюд, один заказ -> много позиций |
| **Транзакционный сценарий** | Оформление заказа — одновременно создаётся заказ и позиции, фиксируется цена |
| **Безопасность** | JWT-аутентификация, эндпоинты защищены по ролям (ADMIN / CLIENT) |
| **Frontend (Vue 3)** | Страницы: вход, регистрация, меню (все блюда), главная (блюда недели), корзина, админ-панель |

---

## 4. Сущности базы данных

| Сущность | Описание |
|----------|----------|
| **User** | Пользователи системы (логин, пароль, роль: ADMIN / CLIENT) |
| **Category** | Категории меню (супы, салаты, горячее, напитки) |
| **Dish** | Блюда (название, цена, описание, категория, флаги: isFeatured, isRecommended) |
| **Order** | Заказы (дата, статус, сумма, способ получения, адрес доставки, привязка к пользователю) |
| **OrderItem** | Позиции заказа (блюдо, количество, цена на момент заказа) |

---

## 5. Ключевые эндпоинты API

| Метод | Эндпоинт | Описание | Доступ |
|-------|----------|----------|--------|
| POST | `/api/auth/login` | Вход, получение JWT токена | Все |
| POST | `/api/auth/register` | Регистрация нового пользователя | Все |
| GET | `/api/public/menu` | Просмотр всего меню | Все |
| GET | `/api/public/featured` | Просмотр блюд недели | Все |
| POST | `/api/client/orders` | Создание заказа | CLIENT |
| GET | `/api/client/orders` | История заказов клиента | CLIENT, ADMIN |
| GET | `/api/admin/dishes` | Управление блюдами (список) | ADMIN |
| POST | `/api/admin/dishes` | Добавление блюда | ADMIN |
| DELETE | `/api/admin/dishes/{id}` | Удаление блюда | ADMIN |
| PUT | `/api/admin/dishes/{id}/featured` | Установка/снятие блюда недели | ADMIN |
| GET | `/api/admin/orders` | Просмотр всех заказов | ADMIN |
| PUT | `/api/admin/orders/{id}/status` | Изменение статуса заказа | ADMIN |

---

## 6. Основные сценарии использования

### Клиент:
1. Регистрируется или входит в систему
2. Просматривает меню (все блюда с фильтром по категориям)
3. Добавляет блюда в корзину
4. Выбирает способ получения (самовывоз / доставка)
5. Оформляет заказ

### Администратор:
1. Входит под учётной записью ADMIN
2. Управляет блюдами (добавление, редактирование, удаление)
3. Выбирает блюда недели (отображаются на главной странице)
